# Diabetes Readmission & Clinical Intervention Queue (Day 4 FDE) A robust backend architecture and data pipeline built for healthcare operational analytics, featuring PostgreSQL ingestion, raw SQL repository patterns, Pydantic data validation, and FastAPI service routing. --- 
## Architecture Overview [ FastAPI Endpoint (main.py) ] │ ▼ [ Business Logic / Services (services.py) ] │ ▼ [ Data Access / Repository (repository.py) ] │ ▼ [ Database Connection Pool (database.py) ] ──> [ PostgreSQL (`diabetes_queue_db`) ] 
### Core Components 1. **`database.py`**: Manages connection pooling via `psycopg` with `dict_row` row factories. 2. **`models.py`**: Defines rigorous Pydantic schemas for patient encounters and care interventions. 3. **`repository.py`**: Encapsulates raw SQL queries (`SELECT`, `INSERT`, `UPDATE`) interacting directly with PostgreSQL. 4. **`services.py`**: Implements domain logic for queue prioritization and workflow state management. 5. **`main.py`**: Exposes clean HTTP endpoints under FastAPI. ---
